# 线程池学习笔记

从零手写一个线程池，用来吃透现代任务调度系统的设计取舍。
这里只放「我自己推导出来的东西」，不放可以直接抄的答案。

## 规则（我自己定的）

- 每环先自己推导，再动手写对应阶段的代码。推导没完成，代码不动。
- 每环结束用自己的话写一份总结，**禁止抄 AI 的措辞**。AI 收进 notes 时只做 Markdown 格式整理，不改写内容。
- 每环总结末尾留一节「这环我卡在哪」，专门记推导时被绊住的地方。
- 间隔复习：1 → 3 → 7 → 21 天。答对翻倍，卡住归零。每次会话开头先抛到期题目。

后面所有涉及「创建线程成本」的数据都基于这个基线，别拿网上的数字直接套。
