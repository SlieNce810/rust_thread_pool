# A3 队列里放的「任务」到底是什么类型

> 状态：推导已完成。**这一版是按推导记录整理的要点版，不是我的原话**，需要把我的原话总结贴回来覆盖。

## 最终类型

```rust
type Job = Box<dyn FnOnce() + Send + 'static>;
```

## 四要素逐个拆

| 部分 | 为什么必须有 |
|---|---|
| `FnOnce()` | 任务只需要被调用一次。用最弱的约束，能接受的任务类型最多。 |
| `dyn` | 每个闭包都是不同的、大小未知的具体类型。要塞进同一个 `VecDeque`，必须抹掉具体类型，只保留「能调用」这个能力 —— 类型擦除。 |
| `Box` | `dyn Trait` 是 DST（动态大小类型），编译期不知道占多少字节，不能直接放进要求 `T: Sized` 的容器。`Box` 把它挪到堆上，栈上只留一个固定大小的胖指针（数据指针 + vtable 指针）。 |
| `Send` | 任务会在**别的线程**上执行，必须允许跨线程转移所有权。 |
| `'static` | 任务在队列里待多久不确定，不能借任何活不了那么久的东西。要么拥有数据，要么用 `Arc`。 |

## `Fn ⊃ FnMut ⊃ FnOnce`

范围从大到小：`Fn` 是最强的约束（能接受的闭包类型最少），`FnOnce` 是最弱的约束（能接受的闭包类型最多）。

**约束越强，能够满足它的类型越少。** 我们只要求「能调用一次」，那就写 `FnOnce`，这样 `move` 闭包、消耗捕获变量的闭包也能交进来。如果写 `Fn`，那些任务就被拒之门外了 —— 这是最小权限原则在 trait 约束上的体现。

## 调用语义（这点是 AI 补的，不算我的推导）

`Box<dyn FnOnce()>` 调用时是「在堆上就地消费」：跑完闭包，只把那块堆内存释放掉，**不会再跑一次析构**。也正因为是消费，`job()` 会把值 move 掉，写两遍 `job(); job();` 是编译错误 —— 「只能调一次」这件事由借用检查器强制，不靠运行时检查。
